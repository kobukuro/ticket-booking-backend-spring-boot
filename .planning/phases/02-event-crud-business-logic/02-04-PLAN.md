<objective>
Implement the Ticket resource API with its distinctive DRAFT-event guard: ticket creation, update, and delete are only permitted when the parent event is in DRAFT status. Read operations (GET) are always allowed. The guard is enforced in the service layer by loading the parent event and checking its status before any mutation.

Purpose: Completes the EVNT-01 requirement (ticket count and price management) and delivers D-05 and D-09 constraints. Runs in parallel with 02-02 and 02-03 — no file conflicts.
Output: TicketRepository update, TicketService, TicketController, TicketControllerIT.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-12 | Elevation of Privilege | POST /api/events/{eventId}/tickets — create ticket for non-DRAFT event | mitigate | requireEventInDraftStatus() in TicketService throws HTTP 409 unconditionally when event is not DRAFT; the check happens server-side on every create, update, and delete call regardless of any client-supplied parameter |
| T-02-13 | Tampering | PATCH /api/tickets/{id} — updating ticket for non-DRAFT event | mitigate | TicketService.update() calls requireEventInDraftStatus(ticket.getEvent()) before applying any changes; no mutation occurs if the guard fails |
| T-02-14 | Tampering | PATCH /api/tickets/{id} — forcing ticket to arbitrary TicketStatus | accept | Phase 2 has no auth layer; business rule for ticket status changes (AVAILABLE → BOOKED → etc.) belongs to Phase 4 ticket-service; Phase 2 accepts any TicketStatus value in UpdateTicketRequest since organizer controls DRAFT-state tickets |
| T-02-15 | Tampering | POST /api/events/{eventId}/tickets — price manipulation | accept | No auth in Phase 2; price validation (non-negative, maximum) belongs to Phase 3 Bean Validation (QUAL-01); service stores whatever price is provided |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan |
</threat_model>

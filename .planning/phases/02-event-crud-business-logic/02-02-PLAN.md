<objective>
Implement full CRUD REST API for the Venue and Performer resources. These resources must exist before event creation workflows can be tested (events reference a venueId and performerIds). Both services follow identical structural patterns: @Transactional(readOnly=true) at class level with @Transactional override for mutating methods, ResponseStatusException for 404 signals, and PagedResponse<T> for list endpoints.

Purpose: Enables organizers to manage the supporting resources (venues, performers) before attaching them to events. Parallel with 02-03 and 02-04 — no file conflicts.
Output: VenueService, VenueController, PerformerService, PerformerController, and integration tests for each.
</objective>

  <action>
    Create VenueService.java in the service package. Annotate with @Service and @RequiredArgsConstructor. Apply @Transactional(readOnly = true) at the class level so all read methods keep the JPA session open during mapper calls. Inject VenueRepository venueRepository and VenueMapper venueMapper via constructor.

    Add method create(CreateVenueRequest request): override to @Transactional (read-write). Build a Venue entity using Venue.builder() setting name from request.name(), country from request.country(), city from request.city(), address from request.address(). Call venueRepository.save(entity) and return venueMapper.toDto(saved).

    Add method findAll(Pageable pageable): call venueRepository.findAll(pageable) to get a Page<Venue>, call page.map(venueMapper::toDto) to get Page<VenueDto>, then return PagedResponse.of(dtoPage).

    Add method findById(UUID id): call venueRepository.findById(id).orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND, "Venue not found: " + id)). Return venueMapper.toDto(venue).

    Add method update(UUID id, UpdateVenueRequest request): annotate @Transactional. Load venue via findById private helper or inline. Call venueMapper.updateVenueFromRequest(request, venue). Call venueRepository.save(venue). Return venueMapper.toDto(saved).

    Add method delete(UUID id): annotate @Transactional. Load venue via findById (throws 404 if missing). Call venueRepository.delete(venue).

    Create VenueController.java in the controller package. Annotate with @RestController, @RequestMapping("/api/venues"), @RequiredArgsConstructor. Inject VenueService venueService.

    Add @PostMapping method createVenue(@RequestBody CreateVenueRequest request): return ResponseEntity.status(HttpStatus.CREATED).body(venueService.create(request)).

    Add @GetMapping method listVenues(@PageableDefault(size = 20, sort = "name") Pageable pageable): return ResponseEntity.ok(venueService.findAll(pageable)).

    Add @GetMapping("/{id}") method getVenue(@PathVariable UUID id): return ResponseEntity.ok(venueService.findById(id)).

    Add @PatchMapping("/{id}") method updateVenue(@PathVariable UUID id, @RequestBody UpdateVenueRequest request): return ResponseEntity.ok(venueService.update(id, request)).

    Add @DeleteMapping("/{id}") method deleteVenue(@PathVariable UUID id): call venueService.delete(id), return ResponseEntity.noContent().build().

    Create VenueControllerIT.java in the test package. Annotate with @SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT), @AutoConfigureMockMvc, @Testcontainers. Declare a static PostgreSQLContainer field with @Container and @ServiceConnection using image "postgres:17-alpine" — same pattern as EventDataLayerIT. Autowire MockMvc.

    Add test createVenue_returnsCreatedStatus: POST to /api/venues with a JSON body containing name, country, city, address fields in snake_case. Assert HTTP 201 status and that the response body contains a non-null "id" field.

    Add test getVenue_notFound_returns404: GET to /api/venues/ followed by a random UUID string. Assert HTTP 404.

    Add test deleteVenue_thenGetReturns404: POST to create a venue, extract the id from the response, DELETE that venue, then GET the same id and assert 404. This verifies the delete-then-404 contract.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Tampering | VenueController / PerformerController POST and PATCH | mitigate | Separate CreateXxxRequest / UpdateXxxRequest DTOs prevent binding of entity internals (id, createdAt, updatedAt) — only declared DTO fields can be set by callers |
| T-02-05 | Information Disclosure | VenueController GET /api/venues/{id} — 404 on missing UUID | accept | UUIDs are non-sequential; guessing a valid UUID is computationally infeasible; 404 does not disclose whether adjacent IDs exist |
| T-02-06 | Tampering | JPA queries via VenueRepository / PerformerRepository | accept | All queries use Spring Data named-method derivation or JpaRepository methods — parameterized queries by construction, no string concatenation of user input |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new packages in this plan |
</threat_model>
